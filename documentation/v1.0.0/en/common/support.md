# Help, Feedback, and Security Reports

Start with the guide that matches what you are doing:

- Use the **User documentation** for chats, models, Workspace, personal settings, sharing, and other day-to-day features.
- Use the **Administrator documentation** for installation, server operation, Admin Settings, access control, providers, backups, security, and troubleshooting.
- If a feature is missing from your account, ask an Omlorix administrator first. Availability can depend on your group, the selected model, or services configured for your installation.

## Ask for help or report a problem

Search the [Omlorix issue tracker](https://github.com/phinaldoo/omlorix/issues) before opening a new issue. For a useful report, include:

- the Omlorix version and, for server problems, the installation method;
- what you were trying to do and which account role was affected;
- the exact steps needed to reproduce the problem;
- what you expected and what happened instead; and
- relevant, redacted messages or screenshots.

Remove passwords, provider credentials, access tokens, private addresses, prompts, uploaded files, personal data, and other confidential information before posting diagnostics publicly.

Feature requests and documentation feedback also belong in the [issue tracker](https://github.com/phinaldoo/omlorix/issues). External code, documentation, translations, designs, patches, and other material for inclusion are not currently accepted.

## Report a security issue privately

Report suspected vulnerabilities through GitHub's
[private vulnerability reporting](https://github.com/phinaldoo/omlorix/security/advisories/new).
Do not disclose vulnerability details in a public issue, pull request, discussion,
or comment.

Include the affected version, safe reproduction steps, expected impact, and a redacted proof of concept when available. Never send working credentials or unrelated user data.
