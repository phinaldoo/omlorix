# Security

Open **Settings > Security** to manage the controls available to your account.

## Privacy

- **Profile Visibility:** choose whether your profile is **Public** or **Private**. Public visibility can make you available in supported invitation pickers; it does not publish your chats or files.
- **Allow LLM to Access Personal Information:** choose **None**, **All**, or **Custom**. Custom access can include your first name, language, country, time zone, and location.

Use the smallest amount of personal context you need. These choices do not hide information you type in a message, remove earlier chats, or control [Workspace Memories](../10_workspace/12_memories.md), which are managed by group policy.

## Sign-in security

- **Sign-in methods:** set or change a password and connect or disconnect available identity providers. Omlorix prevents you from removing your last usable sign-in method.
- **Two-Factor Authentication:** select **Set Up**, complete recent identity verification, follow the displayed setup instructions, enter the six-digit code, and select **Verify and Enable**. Use **Set Up Again** to replace the configuration or **Deactivate** to remove it. Setup and deactivation both require recent verification. A forced organization policy prevents deactivation.
- **Passkeys:** create and remove passwordless credentials. See [Passkeys](4_passkeys.md).
- **Logged-in Devices:** review device, location, and recent-activity information when available. Select **Log Out** for another session, or **Log Out All Devices** after a lost device, credential change, or suspected exposure. Use the profile menu to log out the current session.

Some sign-in methods can be connected but temporarily unavailable. Keep at least two usable methods when possible, and use a unique password if password sign-in is enabled.

Email changes, account deletion, two-factor setup or deactivation, passkey changes, connecting or disconnecting a sign-in provider, and adding a password can require recent identity verification. Use an available password, passkey, or two-factor code. If the account has no local verification method, sign in again and retry the action while that authentication is fresh. Security changes can invalidate pending one-time actions or send a notice to the account email.

Never share passwords, passkeys, one-time codes, recovery information, or session details.

If your account is managed by an organization, profile and sign-in controls may be read-only. See [Passkeys](4_passkeys.md), [Change or Set a Password](17_change_password.md), and [Accounts & Switching](16_account_switching.md).
