# Slide Presentations

A model with **Slide presentation** can create and edit a deck of up to 50 slides from a saved Markdown brief.

## Create the deck

Prepare a Markdown file containing the audience, purpose, key messages, evidence, source notes, desired slide count, and visual direction. Save it in Workspace Files, then ask the model to create a presentation from that brief. Include a numbered plan for every slide: its takeaway, supporting evidence or evidence gap, chosen visual, and essential versus optional details. Add relevant approved images and logos. The assistant can prepare additional evidence and assets when suitable tools are available; without them it works from supplied material and identifies material gaps.

Generation can take time while Omlorix builds, renders, and reviews the slides. A presentation specialist keeps your brief in the same conversation while inspecting a separate full-resolution image of every slide and overview sheets, then making targeted corrections. Review also considers the clarity of each takeaway, explanatory visuals, consistent typography and spacing, repetition, and the opening and closing. The specialist identifies slide-specific issues before corrective edits. A completed review indicates the run finished, not a quality certification; check its assessment for unresolved limitations. It may use Code Execution to check calculations or generate chart and image assets when helpful; this is optional. During generation, the sidebar shows the specialist’s live text, reasoning and tool activity using the same transcript view as subagents. You can close and reopen it without losing the current activity. When the specialist finishes, the sidebar automatically switches to the final saved slides; intermediate drafts do not replace the transcript. If the final preview fails to load, the completed activity stays visible with a retry control. Keep the chat open and wait for the presentation card to become ready.

## Review, edit, and present

Select **View Presentation** to open the preview. Scroll vertically through the live, interactive slides, or use **Outline** to jump to a slide. Multiple slides can be visible at once, and the outline and slide counter follow your scrolling. Controls retain their state as you navigate. Select **Present** for the separate single-slide slideshow view.

Use the header's icon-only **Presentation view** button (stacked layers) to switch between **Preview**, **Specialist chat**, and **HTML source**. The specialist transcript is saved with the presentation's tool result in chat history. Reopening the result card restores **Specialist chat**, including after a page reload or switching chats. It is included in chat backup and restore. Older presentations generated before transcript saving was added have this option disabled because their activity was never recorded. Switching views preserves the transcript's reading position, the preview's interactive state, and any unsaved source edits. The menu marks the current view. The pencil button opens the visual editor, and the play button opens **Present**.

**HTML source** edits the entire saved document, including all slides, styles, and scripts. Select **Save** or press Ctrl/Cmd+S to save and refresh the preview. Preview and downloads use the last saved source. **Discard edits and reload** replaces the draft with the server version; a failed save or revision conflict leaves your code intact. HTML editing becomes available when generation finishes. Saving uses the same ownership, validation, audit and revision checks as the full presentation editor. Switching to the full visual editor saves pending source edits first; a failed save keeps you in HTML source. Unsaved source drafts remain local to the currently open deck; specialist transcripts are restored from saved chat history.

The slideshow displays the saved HTML directly, scaled to fit the screen while preserving the slide’s proportions. Text and graphics remain browser-rendered at fullscreen size. Saved decks can open and present before preview images finish loading. Interactive decks can include quizzes, clickable controls, scenario sliders, animated charts, custom slide transitions, public API data, and embeddable websites. Quiz answers and controls survive slide changes within the session; reopening starts fresh. They are not automatically shared with other viewers or saved to your account.

Presentations can also include steps that reveal an explanation, highlight a diagram, or change a chart. In **Present**, Right/Down/PageDown/Space and the Next button advance a step before moving to the next slide. Left/Up/PageUp/Shift+Space and Previous reverse a step; returning to the previous slide shows its final step. The toolbar shows step progress. Slides without steps navigate as before. Home/End and slide dots jump directly to slides; a direct jump starts at the initial step. Focused inputs and other slide controls retain their keyboard behavior.

Step animations respect reduced motion and settle to the current state when interrupted. Reopening resets presentation steps. The sidebar, editor, review images and PDF/PPTX/image exports show the author's chosen complete state, normally the last step. Exported PPTX files capture that state rather than reproducing the interactive step animations. Ask for staged explanations where they help, and try forward/backward navigation before presenting.

Select **Edit presentation** for direct changes to text, slides, layout, typography, colors, and other visible design settings. **Present** saves your edits and opens the HTML slideshow without waiting for image rendering. The visual editor preserves scripts, network declarations, embed URLs, and export templates, but does not execute the interactions while editing. Use **Present** to try them. The sidebar preview and thumbnails refresh separately. Save and wait for the preview to update before exporting. If the presentation changed elsewhere, reload it before saving.

Click the icon-only **Download** button in the sidebar or presentation editor and choose a format to start downloading. Both the preview sidebar and fullscreen editor offer **HTML source**, **PPTX**, **PDF**, and **Images** downloads. **HTML source** downloads the complete saved `.html` document, including all slides, styles, scripts, embedded assets. The editor saves pending edits first; this download remains available while rendered previews are updating or unavailable. To replace or edit the entire source, use **Code → Whole deck → Apply changes** in the presentation editor. The downloaded source does not include Omlorix’s injected slideshow player or the current viewer’s interactive state; use it for source editing and reuse in Omlorix.

Rendered images are used for sidebar previews, thumbnails, AI visual review, PDF export and image downloads. **PPTX**, **PDF** and **Images** capture the live HTML in the external browser renderer, including JavaScript and internet content. There is no separate static or offline version. Exports start a fresh session, so they do not capture your current slideshow answers or control values. The visual editor also runs the deck's JavaScript and external content. Applying HTML changes or undoing them restarts the scripts. Check exported deliverables for clipping, font changes and missing media.

Public APIs must permit browser CORS requests; websites may prohibit embedding. Decks report errors when a service is unavailable. No account tokens or API secrets should be placed in a presentation.

Presentation records and their stored artifacts are included in **Download Everything** and are restored by the complete account-archive import. A downloaded PPTX, PDF, or image bundle is a deliverable, not an Omlorix presentation archive, and cannot be imported through Data Control. After an account import, open the restored deck and verify its source file, preview, and every output format.

Verify every fact, number, citation, name, date, and image before presenting. Use only material you are authorized to process and distribute.
