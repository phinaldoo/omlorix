# Code Execution

Code Execution lets a compatible model run Python or Bash in an isolated workspace and return calculations, text output, charts, or generated files. It appears only when the selected model and your access allow it.

## Use it

Choose a model that lists **Code Execution**. Describe the task, required language, inputs, expected output, and any constraints. Attach or select only the files needed for the calculation.

For work that matters, ask the model to show the method, name assumptions, validate the result, and save important output as a file. Open generated files before relying on them.

A normal saved chat may reuse its execution workspace for later messages, so variables and temporary files can remain available for a while. The workspace can expire, time out, or be replaced at any time, and Temporary Chats do not preserve it. Download important results or keep them in Workspace Files.

## Limits and safety

Runtime, output, memory, concurrent work, network access, and package installation can be restricted. If a network request or package fails, treat that as a boundary and ask your support contact whether the capability is intentionally unavailable.

Model-generated code can contain mistakes or unsafe operations. Review important code and results, especially calculations, file changes, downloaded data, and dependency choices. Never provide passwords, access tokens, private keys, or information you are not authorized to process.

For an adjustable result inside the chat, see [Interactive Visualizations](23_visualizations.md). For durable editable content, see [Canvas](22_canvas.md).
