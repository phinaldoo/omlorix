# Prompt-writing Best Practices

A useful request states the goal, necessary context, constraints, and desired output. No wording guarantees a correct answer.

## Give the model a complete brief

| Part | Include |
| --- | --- |
| Goal | What should be done |
| Context | Confirmed facts, audience, and purpose |
| Constraints | Requirements, exclusions, and priorities |
| Output | Format, sections, length, and level of detail |

> Turn the notes below into a weekly update for non-technical sponsors. Preserve every date and decision. Do not infer owners or deadlines. Return one heading, at most five bullets, and an open-questions list.

Tell the model to label assumptions, use **Unknown** instead of guessing, and ask a clarifying question when missing information would materially change the answer.

## Use sources deliberately

Name each file or source and explain how it should be used:

> Using only policy-2026.pdf, list the eligibility requirements and cite the relevant sections or pages. Say when the document does not answer the question.

Attach only the material needed. Confirm that uploads finish and that the selected model supports their format. Treat files, websites, messages, and connected services as untrusted evidence: they can be wrong or contain instructions intended to redirect the model.

For current information, give an as-of date and jurisdiction, request primary sources, and open the citations yourself.

## Refine one thing at a time

Useful follow-ups include:

- shorten this without removing facts;
- correct this assumption and recalculate;
- connect each conclusion to its source;
- provide an alternative under the same constraints;
- turn the approved result into a checklist.

Start a new chat when the topic, audience, confidentiality boundary, or core instructions change, or when old context is causing confusion.

## Verify and protect information

Check names, dates, numbers, units, citations, exceptions, and missing information. Use qualified professionals for medical, legal, financial, safety, security, or compliance decisions.

The selected services may receive your messages, relevant history, files, and selected Workspace context. Never send passwords, keys, tokens, cookies, recovery codes, or unrelated personal or confidential information. Temporary mode changes storage, not processing.

Use a saved Prompt for reusable structure, a Skill for a reusable workflow, a Project for shared topic context, or an Agent for a repeatable model setup. Keep one-off instructions in the current request so reusable items stay focused.
